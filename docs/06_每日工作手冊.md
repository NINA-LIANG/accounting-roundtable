# 會計圓桌｜每日工作手冊（排程任務照這份執行）

狀態：v0.1，2026-11-12。執行方式：Claude 排程任務，每天台北時間 07:51，使用需求者現有方案額度（需求者 2026-11-12 同意）。「每天該做的事」為暫定，需求者可改。

## 每天依序做
1. 資料更新：執行 `python3 /mnt/project-files/ai-content-company/kb/sync_laws.py`，再執行 `python3 /mnt/project-files/ai-content-company/kb/verify_kb.py`。記下成功幾部、異動幾條、抽查幾條一致、是否通過。驗證不通過時，當天所有發布相關工作一律停止。
2. 七位員工依序工作，產出放在 `/mnt/project-files/law-site/content/drafts/<日期>/`：

| 角色 | 每天該做的事 | 沒事可做時 |
|---|---|---|
| 研究員 | 讀異動清單與知識庫，提出 3 個題目候選，各附檢索詞與事實清單（每條：說法、條號、知識庫逐字引文）；找不到可引用條文的題目標「知識庫未涵蓋」，不列為候選 | 不適用，每天都要做 |
| 文案寫手 | 把需求者已勾選、尚未寫的題目寫成文章，只能使用該題事實清單裡的法規說法，每個說法附條號與逐字引文 | 寫「今日無工作：沒有已勾選題目」 |
| 腳本寫手 | 把需求者已核准的文章寫成 IG 輪播與 30 秒短影音腳本 | 寫「今日無工作：沒有已核准文章」 |
| 設計師 | 把定稿腳本寫成圖卡文字稿與版面說明（風格 C） | 寫「今日無工作」與原因 |
| 發布員 | 把通過全部關卡且需求者已核准的內容整理成各平台發布包；不自行發布 | 寫「今日無工作」與原因 |
| 數據分析師 | 需求者填入成效數字後做摘要；已發布不到 4 篇不做結論 | 寫「今日無工作：尚無成效數字」 |
| 內容經理 | 檢查前六位是否都有日誌、五道發布關卡結果、哪些事在等需求者 | 不適用，每天都要做 |

3. 遵守憲章 v1.0：禁語、安全界線、引用必須與知識庫原文完全相符（用知識庫 JSON 逐字核對，不靠記憶）、不編造。任何內容都不對外發布。
4. 寫日誌 `/mnt/project-files/law-site/logs/daily/<日期>.md`：資料更新結果一段；七位員工各一筆（做了什麼、產出檔案路徑、有無被關卡擋下、耗時概估）；每日檢查表（每位員工：已做／今日無工作／漏做）；等需求者處理的事。
5. 在 `/mnt/project-files/law-site/logs/監控總表.csv` 追加一列：日期、資料驗證是否通過、七位員工狀態、漏做數、待需求者事項數、當日草稿數、退回數、核准數。
6. 回報：只在有紅燈（資料驗證不通過、有人漏做）或有東西等需求者勾選、核准時，才在討論串用繁體中文發一則 80 字內的訊息並附當日日誌；否則不發訊息。
